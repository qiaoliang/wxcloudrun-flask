## 领域一：认证模块

### 代码串
`auth_bp -> auth/routes.py -> UserService -> User Model -> JWT Token`

### 子领域划分

#### 1.1 微信登录
**核心业务逻辑**:
- 接收微信登录 `code`，调用微信 API 获取 `openid` 和 `session_key`
- 根据 `openid` 查询用户是否存在
- 新用户：自动创建用户账户，分配默认社区，生成 JWT token
- 老用户：更新用户信息，生成 JWT token
- 生成 Refresh Token（7天有效期）用于刷新 Access Token

**关键流程**:
```
前端请求 → 验证code参数 → 调用微信API → 获取openid → 查询用户
→ 创建/更新用户 → 生成JWT Token → 返回token和用户信息
```

#### 1.2 手机号注册
**核心业务逻辑**:
- 验证手机号和验证码
- 检查手机号是否已注册
- 创建新用户账户
- 自动分配到默认社区
- 生成 JWT token 和 Refresh Token

**关键流程**:
```
前端请求 → 验证手机号和验证码 → 检查手机号是否已注册
→ 创建用户 → 分配默认社区 → 生成token → 返回用户信息
```

#### 1.3 手机号登录
**核心业务逻辑**:
- 支持两种方式：验证码登录、密码登录
- 验证码登录：验证验证码有效性
- 密码登录：验证密码哈希值
- 生成新的 JWT token 和 Refresh Token

**关键流程**:
```
验证码登录: 验证验证码 → 查询用户 → 生成token
密码登录: 验证密码哈希 → 查询用户 → 生成token
```

#### 1.4 Token 刷新
**核心业务逻辑**:
- 验证 Refresh Token 有效性
- 检查是否过期
- 生成新的 Access Token（2小时）和 Refresh Token（7天）
- 更新数据库中的 Refresh Token

#### 1.5 账号绑定
**核心业务逻辑**:
- **绑定手机号**: 验证验证码，更新用户手机号
- **绑定微信**: 通过微信 code 获取 openid，更新用户微信信息
- **账号合并**: 检测到同一用户的不同账号（微信账号和手机号账号）时，按注册时间合并账号，保留较早的账号

## 领域二：用户模块

### 代码串
`user_bp -> user/routes.py -> UserService -> User Model`

### 子领域划分

#### 2.1 用户信息管理
**核心业务逻辑**:
- **获取用户信息**: 返回用户的完整信息，包括基本信息、角色、社区等
- **更新用户信息**: 支持更新昵称、头像、地址、座右铭、紧急联系人等
- **上传头像**: 支持图片上传，验证文件类型和大小（最大 5MB）
- **修改密码**: 验证旧密码，设置新密码（6-20位字符）

#### 2.2 用户搜索
**核心业务逻辑**:
- 支持按手机号、昵称搜索用户
- 支持全局搜索和社区过滤
- 支持分页查询
- 返回用户基本信息和社区工作人员状态

**关键流程**:
```
接收搜索参数 → 执行数据库查询 → 过滤结果 → 分页处理 → 返回用户列表
```

#### 2.3 账号绑定
**核心业务逻辑**:
- **绑定手机号**: 验证验证码，更新用户手机号
- **绑定微信**: 通过微信 code 获取 openid，更新用户微信信息
- **账号合并**: 检测到同一用户的不同账号时，合并账号数据

#### 2.4 社区验证
**核心业务逻辑**:
- 验证用户是否属于指定社区
- 返回用户的社区角色信息

## 领域三：社区模块

### 代码串
`community_bp -> community/routes.py -> CommunityService -> Community Model`

### 子领域划分

#### 3.1 社区管理
**核心业务逻辑**:
- **获取社区列表**:
  - 超级管理员：获取所有社区
  - 普通用户：获取可见社区列表
- **获取社区详情**: 返回社区信息、创建者、主管、工作人员统计等
- **获取用户当前社区**: 返回用户当前所属社区信息

**关键流程**:
```
验证权限 → 查询社区 → 格式化社区信息 → 返回结果
```

#### 3.2 社区成员管理
**核心业务逻辑**:
- **获取社区用户列表**: 支持分页、角色过滤
- **移除社区用户**: 将用户移出社区，自动分配到默认社区或黑屋社区
- **获取可管理社区列表**: 返回用户有权限管理的社区（默认7个）

#### 3.3 社区申请管理
**核心业务逻辑**:
- **创建社区申请**: 用户申请加入社区
- **获取申请列表**: 管理员查看待处理的申请
- **批准申请**: 将用户加入社区
- **拒绝申请**: 拒绝用户加入，记录拒绝理由

**关键流程**:
```
用户申请 → 创建申请记录 → 管理员审核 → 批准/拒绝 → 更新用户社区信息
```

#### 3.4 社区工作人员管理
**核心业务逻辑**:
- **添加工作人员**: 支持批量添加，设置角色（staff/manager）
- **移除工作人员**: 移除社区工作人员
- **获取工作人员列表**: 返回社区工作人员列表，支持角色过滤

**权限控制**:
- 只有社区主管和超级管理员可以添加/移除工作人员
- 主管角色只能添加单个用户

#### 3.5 社区统计
**核心业务逻辑**:
- **每日统计**: 返回社区每日打卡统计
- **打卡统计**: 返回社区打卡完成率、规则数量等

## 领域四：打卡模块

### 代码串
`checkin_bp -> checkin/routes.py -> CheckinRuleService/CheckinRecordService -> CheckinRule/CheckinRecord Model`

### 子领域划分

#### 4.1 打卡规则管理
**核心业务逻辑**:
- **创建规则**: 支持多种频率类型（每日、工作日、自定义日期）
- **查询规则**: 查询用户的所有打卡规则
- **更新规则**: 更新规则配置
- **删除规则**: 软删除打卡规则

**规则配置**:
- `frequency_type`: 频率类型（0=每日，1=工作日，2=自定义星期，3=自定义日期）
- `time_slot_type`: 时间段类型
- `custom_time`: 自定义打卡时间
- `week_days`: 星期几（位掩码）
- `custom_start_date`: 自定义开始日期
- `custom_end_date`: 自定义结束日期

#### 4.2 打卡操作
**核心业务逻辑**:
- **执行打卡**: 用户完成打卡，记录打卡时间和内容
- **上报漏打卡**: 用户主动上报漏打卡
- **取消打卡**: 取消已完成的打卡

**关键流程**:
```
用户打卡 → 验证规则 → 创建打卡记录 → 更新打卡状态 → 返回结果
```

#### 4.3 打卡历史
**核心业务逻辑**:
- 获取用户打卡历史记录
- 支持日期范围查询
- 支持分页查询

#### 4.4 今日打卡计划
**核心业务逻辑**:
- 根据规则生成今日打卡计划
- 显示打卡时间、状态、是否已完成

## 领域六：短信模块

### 代码串
`sms_bp -> sms/routes.py -> SmsService -> VerificationCode Model`

### 子领域划分

#### 6.1 验证码发送
**核心业务逻辑**:
- 生成6位随机验证码
- 使用哈希算法存储验证码（不存储明文）
- 支持多种用途：注册、登录、绑定手机号
- 频率限制：60秒内只能发送一次
- 有效期：默认5分钟

**关键流程**:
```
接收手机号 → 生成验证码 → 哈希存储 → 发送短信（或Mock） → 返回结果
```

#### 6.2 验证码验证
**核心业务逻辑**:
- 验证验证码哈希值
- 检查验证码是否过期
- 检查验证码是否已使用
- 验证成功后标记为已使用

**环境支持**:
- Mock环境：直接返回验证码（用于测试）
- 生产环境：调用真实短信服务商

## 关键业务流程

### 用户注册登录流程
```
微信登录
  ↓
获取code → 调用微信API → 获取openid
  ↓
查询用户是否存在
  ├─ 新用户 → 创建用户 → 分配默认社区 → 生成token
  └─ 老用户 → 更新用户信息 → 生成token
  ↓
返回token和用户信息
```

### 打卡流程
```
用户打开今日打卡计划
  ↓
获取个人规则和社区规则
  ↓
生成今日打卡事项
  ↓
用户执行打卡
  ↓
创建打卡记录
  ↓
更新打卡状态
  ↓
返回打卡结果
```

### 社区加入流程
```
用户浏览社区列表
  ↓
选择社区 → 申请加入
  ↓
创建社区申请
  ↓
社区主管审核
  ├─ 批准 → 更新用户社区信息
  └─ 拒绝 → 记录拒绝理由
```

### 监督流程
```
用户邀请监督者
  ↓
选择监督规则
  ↓
创建监督关系
  ↓
发送邀请
  ↓
监督者接受邀请
  ↓
建立监督关系
  ↓
监督者查看打卡记录
```

## 设计模式与规范

### 设计模式

1. **三层架构**: 路由层 -> 服务层 -> 模型层
2. **应用工厂模式**: Flask 应用创建和配置
3. **Blueprint 模块化**: 每个功能域一个 Blueprint
4. **装饰器模式**: 使用装饰器进行权限验证

### 编码规范

1. **SQLAlchemy 2.0 API**: 使用新的查询语法
2. **事务管理**: 使用 `@transactional` 装饰器
3. **软删除**: 使用 `status` 字段标记删除
4. **哈希加密**: 手机号和密码使用哈希存储
5. **审计日志**: 记录关键操作日志

### API 规范

1. **统一响应格式**: `{code, msg, data}`
2. **JWT 认证**: 使用 Bearer Token
3. **错误处理**: 统一错误码和错误消息
4. **分页查询**: 支持 `page` 和 `per_page` 参数
